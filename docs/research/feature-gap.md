> 写作时间：2026-10-21 23:35。
> 方法：**先盘家底（项目现状）→ 再盘外部（上轮竞品调研+API 调研）→ 交叉出缺口**。
> 与之前两份调研的分工：竞品报告回答"别人家怎么做"，API 报告回答"数据从哪来"，**本报告回答"我们下一步做哪个"**。

## 0. 一句话结论（先看这个）

**你项目最缺的不是功能，是"已经有的东西没有被看见"。** 详情页其实已经支持 5分/15分/60分/日K/周K/月K，只是藏在分段按钮里没人发现；`engine/` 里聚类+影响引擎+LLM 闸门三件套已经写好但**没接进页面**；腾讯五档数据在快照里就躺着，只是 `tencent.js` 解析时**主动扔掉**了。

所以本报告把功能分成三层：

- **P0（0.5~1 天，零新增源）**：把已有能力打开（周期下拉、五档、拼音搜索、hash 分享图表状态）
- **P1（1~3 天，用已验证的免费源）**：逐笔成交明细、外汇日线、加密降级链、财报/经济日历
- **P2（项目级，值得做但要下决心）**：引擎接线（事件聚类+AI 摘要+影响地图）、多股同列、自选分组

**不要做的事**：图表深度追 TradingView、做社区、接付费源、加第 12 个 tab。

## 2. P0 层：把已有能力打开（零新增源，当天可做）

### 2.1 周期下拉把 5/15/30/60 分钟"翻出来"

**现状**：详情页分段按钮是 `分时 | 5分 | 15分 | 60分 | 日K | 周K | 月K`——7 个周期挤在一行，用户扫一眼只记得"分时和日K"。
**方案**：改成 `分时 | 日K | 周K | 月K | 分钟 ▾`（下拉收 5/15/30/60），与 TradingView/同花顺的周期收纳逻辑一致。
**成本**：纯 UI 改动，零新增源。腾讯 mkline m5/m15/m30/m60 已支持（800 根上限，调研 README §2.1）。
**意义**：上一轮竞品调研的"可借鉴 #1"就是它。

### 2.2 五档盘口（腾讯快照已带，只是没解析）

**实测证据**（本次新抓）：
```
https://qt.gtimg.cn/q=sh600519
f9=买一价 f10=买一量 f11=卖一价 f12=卖一量
f19-f28 = 买二~买五 / 卖二~卖五（一一对应）
ACAO=*
```
**现状**：`tencent.js:parse()` 只取了 f3（现价）/f4（昨收）/f33/34（高低），**f9-f28 五档字段被主动扔掉**。
**方案**：parse 里补 8 个字段的映射，详情页在"分时"下方加一块五档区（卖 5→买 5，220px 高度，照同花顺移动个股页排版）。
**成本**：半天。**这是本轮调研里"免费但已躺在我们手边"的最典型案例**。
**口径**：免费源只有五档（同花顺的"看十档"是 Level-2 付费，别学它在五档旁挂付费 teaser——我们直接给满免费五档）。

### 2.3 搜索拼音联想（大概率半天）

**竞品报告结论**：同花顺/东财的搜索都支持 `gzmt` → 贵州茅台，东财 suggest 接口返回 `PinYin` 字段。
**现状**：我们已经在用东财 suggest（`eastmoney.js` 里有 `searchCandidates`），但**很可能解析层没读 PinYin**。
**方案**：查 `eastmoney.js` 的 `searchCandidates`，把 PinYin 加入匹配维度。**先验证、再开发**——这是竞品报告里唯一一个"花 20 分钟就能确认是不是免费午餐"的项。

### 2.4 图表状态进 hash 分享

**现状**：`#symbol=xx` 只到"标的"粒度；基金对比的深链（`f/start/end/g/n/a/log`）已经是完整版。
**方案**：把详情页的"周期 + 主图指标 + 副图指标"也进 hash（`#symbol=sh600519&period=5min&ma=5,20&pane=rsi`）。
**成本**：1 天。对标 Finviz 的"三态正交全部进 URL"。
**意义**：这是**传播引擎**——别人分享的链接直接复现图表状态，而不是让用户再点三下。

### 2.5 空搜索给 3 个预设 chips（2 小时）

搜索框聚焦且为空时显示可点的预设问题（"今日放量股 / 成交额历史对比 / 今日量能"），照同花顺 AIME chips。
**成本**：2 小时，纯 UI。

## 3. P1 层：用已验证的免费源补数据（1~3 天）

### 3.1 逐笔成交明细（本次实测推翻上一轮结论）

**这是本次调研最大的发现。** 上一轮 API 调研说"免费源里没有真正的 tick 数据"——**错了**。

本次实测（2026-10-21）：
```
https://push2.eastmoney.com/api/qt/stock/details/get?secid=1.600519&pos=-50000
→ HTTP 200, ACAO=*
→ 当天全部明细 2073 笔，最早 09:15:02（集合竞价），最新 11:29:44
→ 字段：时间,价,手数,（未识别列）,方向(1卖2买4集合竞价)
→ 港股 116.00700 可用，美股 105.AAPL 可用
→ 单次最大回溯 2073 笔（约半个交易日），更大 pos 也不变
```

**方案**：详情页加"逐笔" tab，滚动加载；每行 = 时间 + 价 + 手数 + 方向色。
**口径**：这是**分钟级聚合的"分笔"**（东财自家 App 里也叫"分笔"），不是交易所 Level-2 的逐笔——但免费给到这个粒度已经是行业上限。
**成本**：1 天（含 A/港/美三市场联调）。**与 P0.2 的五档配套，详情页从"只有 K 线"升级成"K 线 + 五档 + 分笔"，信息密度对标同花顺个股页。**
**风险**：东财 WAF 封 IP 的老问题——详情页取数频率低（用户点进去才拉），风险可控。

### 3.2 外汇日线（Frankfurter，ACAO=*）

**现状**：宏观页有中美国债收益率曲线、大类资产矩阵，但**没有外汇对**。
**实测**：Frankfurter 免 key、`ACAO: *`、覆盖 USD/EUR/JPY/CNH 等 30+ 货币，日频。
**方案**：宏观页加"外汇对"区块（USDCNH/EURUSD/USDJPY/GBPUSD 四条曲线 + 当日涨跌幅）。
**成本**：半天。**世界基本面板里外汇是不可缺的一块**。

### 3.3 加密降级链（Kraken/Gate/Bitget 作备胎）

**现状**：加密只有 Binance + OKX 两源。
**上轮实测**：Kraken/Gate/Bitget/Coinbase 全部 `ACAO: *` 或回显，且字段顺序/时间戳各不相同（已在 crypto-sources.md 完整记录）。
**方案**：把"加密行情"的降级链从 2 级扩到 5 级（Binance→OKX→Kraken→Gate→Bitget），**adapter 统一处理"毫秒/秒/ISO 时间戳"和"字段顺序"**。
**成本**：1 天（主要是写 adapter 单测）。**上轮报告的 §4 四坑就是这份 adapter 的需求文档**。
**为什么值得**：Binance 在国内可能被 451，而 Gate/Bitget 不会。这条链上线后加密行情的"可用性"从"依赖一家"变成"五家里总有一家活着"。

### 3.4 财报日历 / 经济日历

**现状**：事件页有 GDELT 宏观新闻，但没有**结构化的财报日历和经济数据日历**。
**免费源**：
- 财报日历：东财 `datacenter-web` 有业绩报表/业绩预告（实测可用，lhb.js 已在用这个域名）
- 经济数据日历：FRED（需 key，项目禁用）、Investing.com（有反爬）、新浪（有但不稳定）
**方案**：先做 A股财报日历（东财源现成、免费、有 ACAO 回显）；经济数据日历做"已发生"列表（不做预告，预告没有可靠免费源）。
**成本**：2 天（A股财报日历）+ 1 天（经济数据已发生列表）。
**取舍**：**不做"经济数据预告"**——免费源里没有稳定的预告日历，宁缺毋滥是本项目原则。

### 3.5 多股同列（自选页的杀手级升级）

**现状**：自选页只能看卡片列表，不能**把多只股票的 K 线排在一起对比**。
**竞品参照**：东财自选页的"多股同列"视图是高频功能。
**方案**：自选页加"对比视图"开关，把选中股票的日K 按归一化收益画在同一张图上（复用 `compare.js` 的归一化逻辑）。
**成本**：2 天（复用基金对比的图表层）。
**意义**：这是从"收藏夹"到"工作台"的一步。

## 4. P2 层：项目级功能（值得做，但要下决心）

### 4.1 引擎接线（事件聚类 + 影响地图）

**现状**：`js/engine/` 里 event-engine.js（聚类）、news-engine.js（标准化）、llm-provider.js（AI 闸门）三个模块**已写完但没加载进 index.html**（只加载了 types/geo/impact-engine）。
**它是什么**：把"一堆新闻"聚成"一个事件"，并给出"这件事影响哪些资产"的推理边——WorldMonitor 的 correlation-engine 的对应物。
**方案**：分三步走——
  1. **纯展示**（不动现有 UI）：事件页加"事件聚类"区块，用 mock 数据跑通渲染；
  2. **真实聚类**：把 news-engine + event-engine 接进事件采集管线（GitHub Actions 侧），把聚簇结果写入 `data/events/`；
  3. **影响边可视化**：事件详情页显示"此事件 → 原油 ↑ / 黄金 ↑ / 美股 ↓"这类推理链（impact-engine 已有规则表）。
**成本**：1 周（含采集侧改造）。
**风险**：这是从"数据看板"到"情报引擎"的一步，**做之前要确认这是不是产品想要的方向**。

### 4.2 自选分组（多组合管理）

**现状**：自选是一个平铺列表（watchSort 只有 default/pctDesc/pctAsc）。
**方案**：加分组（Store 的 watchlist 结构加 `group` 字段，UI 加分组切换器）。
**成本**：1 天。
**参照**：东财自选页的"新建组合"——但**不要学它的"指标设置/批量设置"**，那是重型功能，先做"分组 + 切换"就够。

### 4.3 同花顺接入（第三 A 股源）

**现状**：A 股分钟线只有腾讯（800 根上限）+ 东财（有 WAF 风险）两家。
**上轮实测**：同花顺 `d.10jqka.com.cn` `ACAO: *`，分时带均价线+盘后固定价，1/5/15/30/60 分钟 K，日/周/月/年都有，A股/港股（`hk_HK0700`）/美股（`usa_AAPL`）全覆盖。
**方案**：作为东财的 1 级备胎（东财被封时切同花顺）。
**成本**：1 天（JSONP 剥壳 + 分号串解析）。
**为什么不是 P0**：腾讯+东财已经覆盖了分钟 K 的基本需求，同花顺是"韧性"不是"能力"。但它的**分时均价线**和**盘后固定价**是两家都没有的，值得做。

## 7. 两条本次实测留下的技术注记

1. **东财逐笔明细的字段含义**：`时间,价,手数,?,方向`。第 4 列暂未识别（实测值 0~8 不等，疑似"成交性质"或"笔数拆分"），第 5 列 1=主动卖、2=主动买、4=集合竞价。接入前建议用 Level-2 数据交叉验证一次。
2. **东财逐笔的回溯上限**：单次最大约 2073 笔（约半个交易日），更大 pos 不增加。做"全天分笔"需要在采集侧定时拉取并拼接，**不能指望一次 API 拿全天**。
