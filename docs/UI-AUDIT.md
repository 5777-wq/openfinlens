# UI 设计诊断 · 为什么"说不上来的怪"

> **2026-11 更新（已被取代）**：本文是 UI v2 之前的过渡诊断。用户随后裁定「推倒重来」，六条处方全部落地后又整体重做成单一设计语言 **NEXUS 深空终端**（旧 8 套皮肤删除）。现行规格见 [`UI-V2-SPEC.md`](./UI-V2-SPEC.md)。本文保留作历史依据——六个病灶的成因分析仍然成立，处方里的令牌体系被 v2 继承并扩展。

> 2026-10-31 基于 6 屏实拍（瑞士白首屏 / A股热力图 / K线详情 / 事件页 / OLED 纯黑首屏 / 390px 移动端）。
> 结论先行：**不是某个单点丑，而是四组系统性不一致互相打架**。修法不是重画，是立规矩——先统一语言，再继续堆功能。

## 病灶一：红色一词多用（最重）

红同时承担四种含义：①涨跌语义（红涨）；②选中态（顶部 tab 下划线、"市场预测"红底选中、K线页"指标/事件"红描边按钮）；③品牌强调（logo 圆点、"我的自选"粗红线、提醒徽章）；④警示（"数据滞后 3 天"红字）。

后果：满屏红点红字，眼睛分不清哪个红是"在涨"、哪个是"被选中"、哪个是"出问题"。TradingView 不犯这个错——它的蓝是唯一交互/品牌色，红绿只属于涨跌。

**处方**：红/绿只许表示涨跌。选中、品牌、强调全部收敛到每套皮肤唯一 accent（现在就有 accent 令牌，被到处绕过了）；警示用橙。全站 grep 红色系硬编码替换，tokens.test 加"非涨跌元素不得用涨跌色"的结构断言。

## 病灶二：报纸头版和行情终端两种性格打架

每个 tab 顶部一个约 90px 的巨型黑体标题（全球市场/A股市场/全球事件）+ 粗黑分隔线，是杂志头版语言；下面却是 10 秒轮询的高密度终端数据。大标题吃掉 1/8 屏幕但零信息，数据区反而挤。

**处方**：页头降级为"小节头"——12px 大写字距标签 + 一行元数据（标的数·刷新·抓取时间），高度从 ~90px 压到 ~40px，省出的空间还给数据；粗黑分隔线（2-3px）统一为 1px。首屏锚点交给"市场简报带"（它本来就是答案区）。

## 病灶三：卡片语言三种以上并存

同一首屏里：带红竖条的大指数卡、细边框小指数卡、只有下划线的情绪条、灰底虚线空态卡、白底阴影预测卡——圆角、描边、阴影各成体系。tokens.test 管住了颜色令牌，**没管形状令牌**。

**处方**：形状进 tokens——radius 三档（4/8/14）、描边一档（1px）、阴影两档（浅色皮肤用阴影、暗色皮肤一律换 1px 描边）；卡片只有"大卡/标准卡/迷你卡"三种模板。tokens.test 扩展形状断言。

## 病灶四：间距没有 8px 骨架

顶部跑马灯小盒、子分区按钮、卡片内边距、区块间距各自为政（6/10/12/14/16/21px 混用），基线对不齐。人眼对"差一点对齐"极其敏感——这就是"说不上来的怪"的最大来源。

**处方**：spacing 令牌 4/8/12/16/24/32/48 七档，style.css 清一遍 magic number（只小段编辑，混行尾红线照旧）；字号音阶收敛五档（12/13/15/20/32）。

## 病灶五：OLED 纯黑下对比度塌了

暗色版直接沿用浅色皮肤的阴影策略——阴影在纯黑上不可见，卡片和背景失去边界；灰字（标签/注释）对黑底只有约 3:1。所以纯黑版看着"糊"、发闷。

**处方**：OLED/暗色皮肤专用灰阶（文字灰提亮三档），卡片边界一律 1px 描边（可加极弱 1px 高光内描边），禁用阴影。

## 病灶六：移动端细节（390px 实拍）

情绪条行溢出（"3 涨…"数字被裁掉）；顶栏拥挤、汉堡按钮孤立；卡片两列尚可。

**处方**：情绪条改纵向堆叠或收缩标签；顶栏重排（logo 缩为图标、搜索居中）。

## 执行方式

- 本诊断拆成 TV-ROADMAP「P0.5 UI 语言统一」六条，每轮一条，勾选纪律不变（离线全绿 + 评审放行）；
- 涉及 css/style.css 一律小段编辑（混行尾红线）；涉及 tokens.test 扩展的先加断言再改样式（测试先行）；
- 每轮完成后在 OPTIMIZER-LOG 记录"改前/改后"对照说明；视觉冒烟留给人工轮次。
