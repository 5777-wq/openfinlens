# 对标 TradingView · 长期路线图

> 本文件由「持续开发工作流」按小时驱动：每轮取最靠前的未勾选项施工，离线测试全绿后才允许勾选。
> 人工轮次也可直接编辑。进度留痕见 `docs/OPTIMIZER-LOG.md`，家规见 `docs/FIELD-NOTES.md`。

## 使命与纪律

**目标**：企业级、对标 TradingView 的行情终端（网页 + Android App 端，App 是 WebView 直载本站，网页即 App）。

**美学纪律（硬要求）**：动效与显示必须舒服、克制、有品质——时长 150–300ms、统一缓动 token、
只动 transform/opacity/color、尊重 `prefers-reduced-motion`；新组件在暗/亮皮肤下都要核对对比度与层次。
**摸着石头过河**：每轮一个主题，先骨架后细节，每一步都能回滚。

**对标灵感**：[openmarket.xyz](https://openmarket.xyz/)（用户认可的丝滑参考，2026-10-31 点名）。它的手感拆解：①一块画布读完市场（密而不乱）；②找东西零成本（按意思直达）；③图表惯性滚动 60fps；④层级克制。订单簿热图/CVD/清算图**不搬**（需 L2 数据与交易引导，与本项目"纯前端零密钥、只描述事实"定位冲突）。

**抄库纪律**：GitHub 开源实现可自由参考与移植，但只限宽松许可（MIT / ISC / Apache-2.0 / BSD / 0BSD），
保留原版权注释；GPL/AGPL 代码不得进本仓库（本项目 MIT）。

**合规红线（不可协商）**：不展示成交量数据；不出现 Polymarket 品牌字样；不用省略号问句；
内容全中文；只描述事实不荐股；前端零 API key。

**版本号**：动了 `index.html` 资源引用就按单调递增惯例统一 bump（`20261031a` 式，tokens.test 卡一致性）。
