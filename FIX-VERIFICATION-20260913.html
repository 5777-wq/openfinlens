根因：分档维度选错了

新增的换算函数按 symbol 字符串前缀分档：

function amountScale(symbol) { return /^(sh|sz|bj)/.test(symbol) ? 1e4 : 1; }

于是 hkHSI 不匹配 sh|sz|bj → 落到 ×1。但实测腾讯这个接口里，港股个股和港股指数的 f[37] 单位并不一样：

　at openDetail (js/app.js:1100:31)

同一时刻的页面状态

状态栏停在初始文本「加载中…」，即 init() 尚未跑完

app.js:1100 是 el.detailName.textContent = …，而 el 在 init() 的第一行（3415 行）才被填充。但 hashchange / popstate 监听注册在 IIFE 顶层（2914–2915 行），早于 init() 执行。

  • 脚本在 <body> 末尾同步执行时，document.readyState === 'loading' → init 被推迟到 DOMContentLoaded；
  • 从「监听器就位」到「el 构建完成」之间存在一个窗口；
  • 窗口期内若发生 hash 导航（用户点分享链接、或加载慢时脚本抢先响应），openDetail 就会命中还是空对象的 el。
建议（防御成本极低）
①把 hashchange/popstate 两行注册挪到 init() 内部；或 ②openDetail 开头加一句 if (!el.detailName) return;。两种都行，建议都做。

四、为什么 139 项测试全绿，却仍然漏掉这些？

我复跑了 node _test/run-all.mjs：139 passed / 0 failed，你的说法属实。但绿色掩盖了两个问题——都在新增的 _test/detail.test.mjs 里：

T1 测试断言把错误的行为固化成了"规格"

新增断言里写着：

assert.equal(W.TencentSource.amountScale('hkHSI'), 1);
assert.equal(W.TencentSource.amountScale('usINX'), 1);

这两条断言表示"港股指数、美股指数都用 ×1"——而实测证明港股指数必须用 ×1e4。也就是说：现在这条测试不是在防回归，而是在把回归锁死。将来有人想修好它，反而会被这条测试挡住。

建议
把 hkHSI 改成断言 1e4；usINX 如果决定走"不可用→显示 --"，就断言 amount === null。断言应该描述真实世界应该是什么样，而不是描述代码当前做了什么。

T2 量级断言只覆盖了自己修过的两个样本

同文件里的量级测试只测了 sh600519、sh000001、hk00700、usAAPL 四个——正好是作者手工验证过的那四个。指数一个都没测，于是 hkHSI 从 2284 亿掉到 2284 万，测试毫无反应。

建议
把断言改成"对每个出现的市场类别各取一个代表"：A股个股 / A股指数 / 港股个股 / 港股指数 / 美股个股 / 美股指数。每个都给出合理量级区间。这次的教训正是"样本选择决定了测试的有效边界"。
