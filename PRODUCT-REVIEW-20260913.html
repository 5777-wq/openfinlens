一、P0：数据错了 / 功能没了 2 项

P0-1 港股 · 美股 · 美股指数的成交额，全部放大了 10000 倍 数据错误

用户在「港美」板块第一眼看到的不是行情，是万亿级别的假数字。腾讯控股显示成交 66.7 万亿港元，道琼斯显示成交 18.6 亿亿元。这是金融产品最致命的一类错误——不是丑，是错。

P0-2 「世界经济」仪表盘 100% 失效——宏观 tab 打开就是一片空白 功能失效

README 把「世界经济仪表盘·宏观板块独占整屏」列为招牌功能。实测：点「宏观」进去，整屏只有一个标题和一行灰字「世界银行数据暂不可用」。而这不是网络问题——API 完全正常。

页面实际渲染
暂不可用

同一浏览器内直连 API

根因：ISO 两位码 / 三位码不匹配（已实测坐实）

世界银行接口返回的记录里，countryiso3code 是三位码，country.id 才是两位码：

字段实测值（节选）
countryiso3code'CHN' · 'USA' · 'JPN' · 'DEU' · 'GBR' · 'FRA' · 'IND' · 'KOR'

而代码一头一尾用了两套码：

  • js/sources/worldbank.js:38 — 建索引用 out[r.countryiso3code] → key 是 'CHN'
  • js/sources/worldbank.js:57 — 取数用 byInd[k][c.iso] → 查的是 'CN'

两边永远对不上 → 所有指标取值为 null → filled === 0 → return null → 上层渲染「暂不可用」。一行之差，一个招牌功能整体下线。

修复口径
把 out[r.countryiso3code] 改成 out[r.country.id]（或统一迁到三位码）。修复后建议加一条断言：8 个国家 × 6 个指标，至少有 40+ 个非空值。附带说明：目前该请求还没有备源，且不做任何缓存兜底，一旦上游抖动或代码再出问题，这个 tab 就是空白——建议补一个「上一次成功值 + 时间戳」的降级展示。

二、P1：用户能感觉到、但不会当场卸载的问题 12 项

P1-1 首屏最重要的四个大数字，涨跌没有颜色 视觉 / 信息设计

上证 / 恒生 / 标普 / BTC 四格大数字是整屏视觉重心。但它们的涨跌行永远是灰色——用户必须读正负号才知道涨跌，而全站其他所有涨跌都是红绿编码。切「绿涨红跌」时这四格也纹丝不动。

P1-2 手机上提示「滚轮缩放 · 右键复位」 移动端文案

375px 视口下，热力图浮层提示实测仍为「滚轮缩放 · 拖拽平移 · 右键复位」。触屏设备既没有滚轮也没有右键，复位在手机上等于不可用（代码里按钮路径可以复位，但提示没告诉用户）。

建议
按指针类型分叉文案：触屏 → 「双指缩放 · 单指平移 · 双击复位」；鼠标 → 保持现文案。同时在移动端把「复位 ×1.0」按钮默认显示出来（现在要缩放后才出现，触屏用户可能永远找不到）。

P1-5「47 个标的」这个数字，在任何 tab 都不对 文案 · 数据一致性

切到「A股」，页面只渲染 8 行，标题下却仍然写着「47 个标的」。切「港美」是 15 行，还是写着 47。数字与实际所见不符，用户第一反应是「是不是没加载完」。

P1-6 时间标注：把「抓取时间」当成「行情时间」，且「实时」名不副实 数据时效

今天是周日，A股 / 港股 / 美股全部休市（徽章正确显示了「周末休市」✓）。但标题下写着「最后更新 18:31:10」，热力图角标写着「实时」。用户会以为这些是刚刚的实时行情——实际是上周五的收盘数据。

  • #marketSub 的「最后更新」取的是本次抓取时刻，不是行情时间。
  • 热力图角标的「实时」（app.js:700）真身是 via 的措辞——表达「数据来自主源直连」，不是「数据是实时的」。用词和语义脱节。
建议
全站统一成双时间标注：行情时间（如「9-11 收盘」）+ 抓取时间（如「18:31 更新」）。热力图角标把「实时/备用源」改为「主源直连 / 备用源」，时效另立一格。

P1-7 事件采集已经停摆 ~33 小时，页面不告警 数据新鲜度

事件页所有条目都是 9-12（昨天），而页面只写「更新于 09:10:36」——没有日期。今天是 9-13 18:40，用户几乎必然误读成「今天早上刚更新」。

同时页面上出现三个互相打架的数字：21 个事件点、覆盖 66 条事件、列表实际 80 条，而数据文件里是 102 条。用户无法判断「到底有多少事件」。

建议
①时间戳一律带日期，并加「距今 N 小时」；②超过阈值（如 2 小时）时把状态角标升级为显式警示；③把「点 / 条」的口径在界面上说清楚（例如「地图显示 21 个聚合点，对应 66 条事件；时间轴共 80 条」）。

P1-8 详情页收藏按钮：读屏器不知道它是什么，手指也不好按 无障碍 · 触控

详情页的 ☆ 是全站唯一的收藏入口，但它的完整 DOM 是：

<button class="star" id="detailStar" title="收藏">☆</button>

  • 没有 aria-label：读屏器只会念一个孤立的符号。
  • 没有 aria-pressed：已收藏 / 未收藏的状态读不出来。（卡片墙上的星标有 aria-pressed，详情页这颗漏了。实测点击后类名确实从 star 变成 star on、符号从 ☆ 变 ★，视觉是对的。）
  • 尺寸 32×32px，低于 44px 最小触控目标；返回按钮 66×30px、设置按钮 50×30px 同属偏小。

P1-9 产业链用内部口径说话：「15A · 2US」 文案可读性

产业链每一行链名后面跟一串代码式标签。放大后确认是「15A · 2US」「20A · 6US」「19A · 7US」——含义是「15 只 A 股 · 2 只美股」。这是数据维护口径，不是用户语言。

  • 建议直接写「17 只成分股（含 2 只美股）」，或干脆只显示总数。
  • 每行右侧的橙色强度条没有刻度也没有图例（归一化到当日最大波动），用户不知道长条代表几个点。
  • 行尾展开箭头 › 颜色过淡，展开的可发现性偏低。

P1-10 成交额缺失时，用成交量顶上来显示 数据口径

卡片行与详情页共用同一段兜底逻辑：

js/app.js:354 / 539 — q.amount ? fmtVol(q.amount) : (q.volume ? fmtVol(q.volume) : '')

当上游没返回成交额时，会把成交量（股 / 手）填进「成交额」这一列。两个量纲完全不同，但界面上看不出任何区别，也没有降级角标。深夜清算时段东财会把涨跌幅回成 "-"（README 自己记录过这个坑），同类字段缺失去概率并不低。

建议
成交额缺失就显示 --，绝不用另一个量纲顶上；如果确实想展示成交量，另起一列并标明单位。

P1-11 页脚的「数据源状态栏」是给开发者看的 文案分层

每个板块底部都有一行常驻小字，正常时是：

eastmoney 正常 tencent 正常 binance 正常 em-clist 正常 em-search 正常

上游抖动时变成：

em-clist 降级 eastmoney 降级 sina 降级 tencent 降级 binance 降级 okx 降级 brk 正常 gdelt 正常 lhb 降级

普通用户看不懂 em-clist／brk／「降级」，只会感到恐慌（「我看到的数字是不是坏的？」）。这行信息对排障有用，但应该收进「开发者：数据源自检」里，或对普通用户折叠为一句人话：「部分数据源响应异常，已自动切换备用源」。

三、作为产品经理，我会提的 14 条改进

信息架构

A1 宏观 tab 的定位需要重新想一遍

现在的设计是「宏观 tab 独占整屏给世界经济年表」。问题是：外汇（美元离岸人民币）、大宗商品、国债收益率这些看盘刚需，被挤到「全部」里去了；而世界经济是年度数据，看盘的人一周看一次都算多。目前又因为 P0-2 整屏空白，等于这个 tab 是完全空的。建议：宏观 tab 拆成「利率/汇率/商品（实时）+ 世界经济（年度）」两段，或者把高频的汇率商品提到前面。

A2 首屏动线：最重要的大盘宽度要滚两屏才看得到

首屏是 47 行卡片墙（实测页面高 4342px），热力图与情绪指标在下面。但「今天市场是普涨还是普跌」这种第一问题的答案，其实在情绪指数里——而它被埋在第二屏。建议把情绪指数/涨跌家数做成 hero 右侧的一格常驻指标，或提到卡片墙之上。

A3 一级 tab 有 9 个，认知负担偏重

9 个一级 tab + 事件页内 3 个子视图。而且「加密」会因为合规开关（?crypto=off）整体消失，导航结构不稳定。建议按「看盘 / 挖掘 / 我的」三组归并，视觉上做成分组。

功能缺口

B1 没有价格提醒——金融看板最高频的刚需

有自选、有行情、有 10s 轮询，但没有「到价提醒」。哪怕只做浏览器内通知（甚至只在标签页标题闪烁），价值都远大于再加一个板块。

B2 没有导出

自选、龙虎榜、席位轨迹、产业链成分股，全都无法导出 CSV。做研究的人会直接放弃。

B3 自选太薄

只有「收藏顺序 / 涨幅↓ / 涨幅↑」。缺：清空/批量删除、拖拽排序、备注、分组、列头（实测自选页没有列头，用户不知道最后那个数字是成交额）、以及复制成文本/分享。

B4 搜索的可发现性没做完

  • placeholder 是「搜索代码 / 名称」，但实测支持拼音（maotai 能命中）—— 能力没告诉用户。
  • 结果列表没有「共 N 条」，也没有「查看更多」。
  • 下拉默认不高亮第一项，键盘用户不知道当前选中谁。

B5 详情页缺几个「顺手」的动作

只有「看图 + 收藏」。缺：复制链接 / 分享、加入自选的文字提示（现在只有一个 ☆ 符号）、到价提醒入口、前后切换标的（左滑右滑 / 上下键）。

体验细节

C1 术语门槛偏高，且解释藏在角落

「情绪指数」「环节强度」「席位」「净额」「D1 / D5」「15 榜 / 15 次」「聪明钱」—— 这些词对非专业用户是墙。虽然各处都有一段免责说明（做得挺认真），但那是免责口径，不是科普口径。建议关键术语做 hover 气泡或首次出现时的一行解释。

C2 英文事件影响阅读

GDELT 来源的条目大量是英文标题（实测混在中文快讯中间），中文用户需要二次翻译。建议对英文条目做机器翻译的「一键显示中文」或至少标注语言。

C3 设置项过少，且无法恢复默认

目前只有 3 项：涨跌配色、刷新间隔、降级角标。缺：默认打开板块、主题（目前只有深色）、热力图默认口径、数据源偏好、以及「恢复默认设置」。

C4 图表带着 TradingView 的品牌水印和外链

K 线图左下角有 TradingView 标识，实测其中包含指向 tradingview.com 的外链（带 utm 参数）。这是 lightweight-charts 的 Apache-2.0 attribution 要求，属于合规必需，不是 bug。但如果你希望视觉上完全自有品牌（尤其面向客户交付），需要提前知道这一点：可评估购买其无标识授权，或换图表库。

C5 首屏 162 个外部请求

首屏实测发起 162 个外部请求（东财全市场 56 页分页 + 美股约 13800 只全量）。桌面宽带下没问题（DOM ready 660ms），但移动网络下流量与电量代价明显。可考虑：非「A股/情绪」视图时降低全市场抓取频率、或先给 Top N 再后台补全。

C6 数字精度与格式不完全统一

席位表里出现 4.20亿 / 7516.8万 / 9956.9万 / 0 混排，同一列既有亿又有万、小数位也不一致。建议同一列统一量纲与精度（如全部「万」保留一位），并保持右对齐。

四、做得好的地方（这些别动）

✓1 降级链是真的能扛 实测

我用 CDP 拦掉了 111 个外部请求（保留页面自身 13 个），模拟「所有上游全挂 + 首次访问（无缓存）」的最坏情况：

  • 没有白屏、没有弹窗报错、没有骨架屏卡死；
  • 卡片墙 → 「数据加载中，或该分类数据源维护中…」；hero → 「等待数据」；情绪 → 「暂无市场宽度数据」；席位/龙虎榜 → 「暂不可用（东财数据中心未响应，稍后自动重试）」；
  • 基于静态 JSON 的伯克希尔 13F 照常显示（说明架构分层是对的）；
  • 来源状态如实标出 7 个源「降级」。

README 说「永不白屏」，实测兑现了。这是项目的护城河。

✓2 性能优秀 实测

DOM ready 660ms，开屏消失 1.85s，行情卡片首次渲染 1.34s。在「无构建、零依赖、纯客户端」的前提下，这个数字很漂亮。正常路径下 console 零报错。

✓3 无障碍基础扎实 实测

9 个 tab 全部带 aria-selected；搜索框有 aria-expanded / aria-controls / aria-autocomplete；详情页 document.title 会随标的更新为「600519 · OpenFinLens」；卡片是 role="button" 且有 aria-label。只有详情页星标（P1-8）漏了。

✓4 键盘导航可用 实测

实测：1 → 全部、4 → 宏观、/ → 焦点落到搜索框，全部生效。配合 Backspace 返回详情。

✓5 口径诚实，是本项目最稀缺的品质

技术面面板明确写「只描述事实与常用读法 · 不构成投资建议」「指标间互相矛盾是常态」；席位页区分「发言 ≠ 交易」；13F 标注报告期与滞后；加密「市值」用 24h 成交额代理并主动声明；外汇无日 K 就诚实显示空态而不是造数据。这种自律在开源项目里很少见。

✓6 交互细节到位

搜索下拉带市场标签（「贵州茅台 600519 沪A」）；空自选引导「点击卡片右上角 ★ 添加自选」；组合概览有「等权平均 · 1/1 只有行情」这种小字交代口径；收藏、排序、星标切换实测均正常。

✓7 合规开关是真的干净 实测

?crypto=off 下加密 tab、加密热力图 pill、加密新闻筛选整体消失，卡片墙分组从 8 降到 7，其余功能不受影响。

一件需要说明的环境事实

3D 地球的初始抛出过一次 WebGL 异常（globe.gl.min.js 内部 Error code 1），但地球最终渲染成功，所以我没有把它记为 bug。不过它暴露了一个风险：页面没有捕获 WebGL 初始化失败，兜底节点 #globeFallback 始终保持 hidden。也就是说，如果用户在禁用 WebGL / 老显卡 / 远程桌面的环境打开事件页，很可能看到黑屏且没有任何提示。建议补一条「WebGL 不可用 → 自动切平面地图并提示」的兜底（平面地图是纯 Canvas，不依赖 WebGL，现成的备选方案就在旁边）。
