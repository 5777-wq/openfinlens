一、新发现：失业率指标代码是错的 一行修复 · 影响 1/6 的指标

N-1 「失业率」整列永远是 --，因为世界银行根本没有这个指标代码 P1

世界经济仪表盘 6 个指标里，「失业率」这一列 8 个国家全部显示 --。上轮我把这当成"世界银行没发布数据"就放过了——这是我的漏判。这次我逐个核对了指标代码，发现是代码写错了。

js/sources/worldbank.js:14

unemp: { code: 'SL.UEM.TOTL.ZG', label: '失业率', hint: '总失业 %' },
                     ^^ 这个后缀不存在

实测对比（同样的 8 国、同样的 mrnev=1 参数）：

指标代码返回国家数数据年份样本值判定
SL.UEM.TOTL.ZG（现用）0——无效代码
SL.UEM.TOTL.ZS（正确）8全部 2025中国 4.615% · 德国 3.711% · 法国 7.542% · 英国 4.746%可用

世界银行的失业率标准口径就是 SL.UEM.TOTL.ZS（Unemployment, total — % of total labor force, modeled ILO estimate）。ZG 这个后缀在世行指标表里不存在，所以接口对它返回空数组——而代码把"空数组"当作"该国无数据"，于是一整列静默失效。

为什么这个缺陷能躲过三轮验收
第一轮我验证的是"世界经济表从空白变成有数据"（P0-2 修复）——当时看到 8 国 × 6 指标里"绝大多数有数"就通过了。但"有数据"和"数据齐"是两回事，而"数据齐"和"数据对"又是一回事。这一列从第一天起就是空的，没有任何变化，所以"修复前后对比"这种验证方式天然看不见它。
这正是我在番茄钟那边强调的同一条：验证要看数据本身对不对，不能只看"有数据"。
修复建议
把 'SL.UEM.TOTL.ZG' 改成 'SL.UEM.TOTL.ZS'，一行。改完加一条断言：6 个指标各自至少返回 6 个国家的非空值——用"每列都要有数"来防这类静默失效，比"总共非空数 ≥ N"更严格（现在的测试用的是后者，一整列空缺并不会让它红）。

二、新发现：世界经济表的数据呈现 2 项 · P2

N-2 跨 34 年的数据被放进同一个色阶里横向比较

「政府债务」这一列的真实数据是这样的：

国家显示值数据年份年份跨度
德国20.9%19901990 → 2024
跨度 34 年
印度46.5%2018
美国116%2024
英国131%2024
韩国47.8%2024
中国 / 日本 / 法国--—该指标无数据

界面上每格都标了年份（这点做得对），但「列内色阶热图」这件事本身隐含了"同一时间截面的横向比较"。用户扫一眼颜色深浅，会得出"德国债务水平最低"的结论——而那个 20.9% 是 1990 年的西德。拿 1990 年的德国和 2024 年的美国比债务率，比出来的东西没有意义。

建议
三个层次，任选：①色阶只在同年份的国家之间生效，跨年份的格子用中性底；②列头标注"数据年份跨度大，勿直接横比"；③把年份差异过大的行（德国 1990、印度 2018）视觉上分离出来（如加淡化或加"数据陈旧"标记）。

N-3 「整列无数据」和「该年未发布」被当成同一件事

表格底部现在的说明是：「缺失 = 世界银行该年尚未发布」。但实际存在两种性质完全不同的缺失：

  • 指标级缺失：失业率——该指标代码无效（N-1），8 国全空；政府债务——中国/日本/法国根本没有这个口径的数据（世行只提供中央政府债务）。
  • 年份级缺失：某国某年数据尚未发布。

前者不是"等一等就会有"，用户对着它刷新是没用的。建议至少把「失业率」整列的情况说清楚（修掉 N-1 后这一列就正常了），并在政府债务列头注明它是"中央政府债务口径、覆盖不全"。

五、一个必须澄清的环境问题：本地数据滞后 23 小时

E-1 事件数据滞后不是采集故障，是本地仓库没同步

页面显示「更新于 9-13 22:08 · 数据已滞后 23 小时」。看起来像采集停摆，但查证后不是。

检查项结果
本地 data/events/global-events.jsongeneratedAt = 2026-09-13T14:08:07Z（= 北京 09-13 22:08）
本地仓库 HEAD6b0baf1（09-13 23:55）
远程仓库最新提交（GitHub API 实测）af025ef 2026-09-14T06:47Z + 0e1543b 09-14T01:30Z + bc7851b 09-13T23:31Z … —— 采集工作流一直在正常跑

结论：远程有 5 个更新的提交（含 4 次 data refresh），本地都没拉。页面上那个"滞后 23 小时"是本地预览的产物；部署到 GitHub Pages 的线上版本会拿到最新数据。做一次 git pull 即可消除（我没有执行——那会改动你的工作区）。
